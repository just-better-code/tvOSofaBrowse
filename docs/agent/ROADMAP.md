# Роадмапа — tvOSofaBrowse

Оновлено **2026-10-12**. Тут лише незавершені пропозиції та відкладена робота. Пункт у roadmap не є дозволом на реалізацію чи доказом помилки. Виконані етапи, результати перевірок, експерименти й рішення щодо закритих напрямків — у [dev history](DEVELOPMENT_HISTORY.md); чинна поведінка — у [посібнику](../USER_GUIDE.md).

## WebKit і JavaScript — подальші вдосконалення

- **Організація зв’язаного мосту.** Розглянути поділ вихідного коду interaction/media/fullscreen за призначенням без порушення спільного стану, API нативних команд і повідомлень між фреймами. Для нових незалежних помічників обирати isolated world, якщо потрібні API доступні. Підміни API сайту мають залишатися в page world; ізоляція змінних не ізолює DOM і не обходить сторонні iframe.
- **Межі runtime-адаптера.** Зосереджувати динамічні WebKit-виклики в адаптері з перевірками можливостей та запасними шляхами. Не видаляти селектори, потрібні для браузера на tvOS, лише заради копіювання типізованого iOS-коду. Зміни сховищ підпорядковуються правилам резервування.
- **Відновлення після завершення вебпроцесу.** Перевірити відновлення сторінки й позиції прокручування. Як окремі кандидати — повідомлення з ручною дією після вичерпання автоматичних спроб та визначена поведінка неактивної вкладки після завершення її процесу.
- **Cookies та авторизація після перезапуску — відкладено.** Завершити живу перевірку збереження session cookies і входу на сайт після повторного запуску. Не підміняти сайтове сховище резервуванням окремих виборів сторінки. Попередні спостереження й обмеження перевірки шукати в dev history.

## Iframe та fullscreen — лише за конкретним збоєм або новим запитом

Мета подальшого дослідження — керування плеєром самого сайту з пульта, включно з вкладеними й сторонніми фреймами. Не повертати експеримент iframe-to-VLC чи окремий AVPlayer.

- **Обробка у власному фреймі.** Дослідити адресні запити скрипту відповідного фрейму для елемента під курсором, поля, відео, hover і dragging замість рекурсивного доступу батьківського документа до стороннього DOM.
- **Ідентичність і життєвий цикл.** Перевірити можливості `WKScriptMessage.frameInfo` та адресного JS на tvOS; звіряти джерело, тип повідомлення й актуальність документа. Урахувати Shadow DOM, координати та canvas-плеєри.
- **Умовна підміна fullscreen.** Порівняти нативні можливості з поточним мостом і визначити синхронізацію після входу/виходу, навігації та видалення фрейму. Референс: [FullscreenHelper Firefox](https://github.com/mozilla-mobile/firefox-ios/blob/371a1b51c54645dbcbd7ad41d1479c7a9e5850f8/firefox-ios/Client/Frontend/UserContent/UserScripts/AllFrames/WebcompatAtDocumentStart/FullscreenHelper.js).
- **Навігація iframe.** Перевірити незалежність історії, адреси й назви головної вкладки; окремо обробляти `targetFrame == nil`.
- **CSS hover.** Оцінити підхід із [огляду форків](FORK_SURVEY_2026-10-04.md) та [плану iframe](plans/iframe-player-controls.md#candidate-from-an-upstream-fork-css-hover-emulation).

Референси й межі: [Firefox iOS](FIREFOX_IOS_IFRAME_RESEARCH.md), [план iframe](plans/iframe-player-controls.md), [медіакерування](plans/native-iframe-media-controls.md).

## Навігація й фокус — кандидати

- **Повернення фокусу.** Після діалогу повертати його на вихідну плитку/рядок. Оцінити тимчасове запам’ятовування DOM-елемента перед меню за прикладом `FocusedDOMElementCache` Firefox TV; відновлювати лише в тому самому документі, якщо елемент існує та приймає фокус.
- **Послідовна дія Back.** Визначити порядок виходу з вкладених параметрів, закриття меню та навігації сайту. Референс: `ScreenControllerStateMachine` Firefox TV. Зберігати документовані кнопки й платформний вихід.
- **Внутрішня навігація вебплеєра.** Дати плеєру обробити власну навігацію перед браузером там, де підтверджено проблему; не додавати історичний обхід конкретного сайту без перевірки.
- **Фокус після вимкнення елемента.** Перевірити передбачуваний перехід, коли кнопка/рядок зникає або стає недоступним. Референс: `ToolbarUiController` Firefox TV.
- **Дії через утримання Center.** Додавати параметри іншим плиткам лише за реальної потреби, використовуючи спільний обробник.

## Курсор і зворотний зв’язок — кандидати

- **Плавність курсора.** За видимого тремтіння/затримки порівняти `CursorModel` і `CursorView` Firefox TV та узгодити курсор, hover і лупу з кадрами.
- **Рух біля краю.** За конкретного відгуку оцінити точність наведення, розгін і пропорційність edge scrolling. Зберігати погоджені короткі кліки, held-scroll параметри, відсутність swipe scrolling/інерції та негайну зупинку після вводу чи відкриття меню.
- **Досягнення межі.** Розглянути стриманий сигнал, щоб нерухома сторінка не здавалася завислою; не повторювати його протягом утримання.
- **Контекстні підказки.** Коротко нагадувати про меню або доступні дії, зберігати налаштування підказок і ховати їх під час перегляду/fullscreen. Референси: `WebRenderHintViewModel`, `OverlayHintViewModel` Firefox TV.
- **Підтвердження дії.** Повідомляти про додавання/видалення обраного без модального діалогу й втрати фокусу. Підтвердження руйнівних масових дій зберігати. Референс: `ToolbarViewModel` Firefox TV.
- **Пояснення іконок.** Додавати підказку при фокусі лише для незрозумілої іконки, утримання або наслідку, без дублювання наявного тексту.

## Обране та огляд вкладок

- **Перевірка життєвого циклу вкладок.** Спостерігати вивантаження неактивної вкладки після таймера, повернення до неї та відновлення навігації/позиції/прев’ю після призупинення застосунку. [План](plans/inactive-tab-ttl.md).
- **Перевірка огляду.** Переконатися, що показ cached previews не завантажує неактивні сторінки, а вибір картки відновлює потрібну вкладку.
- **Запасна мініатюра.** За невдалого знімка зберігати корисне старе прев’ю або показувати домен/знак сайту. Однорідне зображення саме по собі не є доказом невдалого знімка. Референси: `PinnedTileScreenshotStore`, `PinnedTilePlaceholderGenerator` Firefox TV.
- **Сітка обраного — окреме рішення.** Порівняти нативні рядки з опційною сіткою прев’ю й назв за `home_tile.xml` Firefox TV; зберігати кнопки пульта й стиль меню. Заміна списку не погоджена.

## Історія переглядів

- **Пошук і фільтри.** Пошук за назвою/доменом і швидкі фільтри «Сьогодні / Останні 7 днів / Усе».
- **Групування за датою.** Розділювачі й перехід між групами замість суцільного списку All History.
- **Повернення на початок.** Окрема дія або індикатор позиції для довгого списку.
- **Масове видалення.** Оцінити кількість вибраних записів і підтвердження великої вибірки, без дублювання Clear All.
- **Великі колекції — за запитом на перевірку.** Оцінити відкриття/прокручування 1000+ записів на ізольованих даних. Лише за підтверджених затримок розглядати порційне завантаження й оновлення лічильників без перечитування всієї історії.

Зберігати Center для відкриття й Play/Pause для позначення рядка. Ці пропозиції не означають доведених дефектів.

## Введення адреси

- **Чернетка.** Перевірити, що redirect або зміна навігації не перезаписує текст під час редагування. Спершу звірити чинний діалог; референс — `ToolbarUiController` Firefox TV.
- **Локальні підказки — окреме рішення.** Розглянути збіги з обраного, доменів та історії з явною дією пошуку. Відрізняти адресу від пошуку й завантажувати лише після підтвердження.

## uBlock — відкладені адаптації

Поточний погоджений обсяг не розширювати без нового запиту. Ціль майбутніх етапів — максимальна практична підтримка full uBO у WKWebView. Спершу шукати готові механізми в uBO, Brave і Firefox; розділяти можливості спільного рушія та WebExtension host API. Нативні content rules лишаються fallback для неперехоплених ресурсів.

| Відкладений напрямок | Наступна робота та референс |
| --- | --- |
| Динамічна політика | Destination/type/URL controls у TV UI та узгодження ширших allow/noop із нативними chunks; `dynamic-net-filtering.js`, `url-net-filtering.js` |
| Redirects і підміни | General redirects/surrogates, network response-header/body delivery, ширше поширення modifiers і network cosmetics; `redirect-engine.js`, `redirect-resources.js`, fetch/XHR helpers. Не винаходити новий транспорт без підтвердженої потреби; VAST/VMAP/playlist edits потребують конкретного формату/шляху |
| Сумісність списків | Повні аргументи й aliases AdGuard; аудит процедурного runtime/lifecycle; `static-filtering-parser.js`, `resources/`, `contentscript-extra.js`. Розрізняти синтаксичну помилку й правило без delivery adapter |
| Діагностика | Точний network source/line provenance та ширше спостереження allowed/blocked/modified; `logger.js`, `reverselookup.js`. Не видавати прогноз matcher за спостережене блокування |
| Живі перевірки | Blocked-page dialog/focus, повна поведінка Block/Allow/Use Filters/Inherit, широкі lifecycle/CSP сценарії; врахувати неперервні DOM queries/RegExp та відкладені scans великих документів |
| Пам’ять — повернутися пізніше | Продовжити зменшення споживання без вилучення функцій master, вимкнення списків або послаблення правил. Окремо профілювати холодну компіляцію/відновлення мережевого рушія, співіснування старого й нового runtime під час оновлення, копії WKUserScript у вкладках/фреймах та повні проміжні рядки списків. Зіставляти пік підготовки й пам’ять після завершення; підтверджувати рівність правил, винятків, порядку та залежностей. Референси: серіалізовані блоки uBO (`static-filtering-io.js`), hostname retrieval та механізми компактного зберігання Brave без заміни погодженого uBO matcher. Перевірка повного застосунку на TV потребує окремого дозволу; локальний RSS компілятора не є бюджетом TV |
| Workers — окреме повернення до дослідження | HTTP(S), Shared/service workers та чужі Blob realms лишаються на native WebKit. Перш ніж відновлювати custom-protocol напрямок, розв’язати cookies та реальне скасування underlying transport; не заявляти повної uBO-еквівалентності |

Контекст: [огляд здійсненності](UBLOCK_REFERENCE_REVIEW.md), [матриця](plans/ublock-runtime.md), [межі HTTP workers](plans/ublock-http-workers-handoff.md), [поточне покриття та ліцензії](../../_Project/Vendor/UBlock/README.md). Під час майбутніх змін зберігати trust gating, пріоритет винятків, актуальність документа/політики й чинний захист при перебудові.

Відхилено об'єднання DNS-доменів через `|` у `url-filter`: WebKit content blocker не підтримує цю альтернативу. Майбутню оптимізацію нативної компіляції починати з поетапних таймінгів і перевірки підтримуваного синтаксису WebKit; не повертати цей варіант групування.

## Торент-клієнт — подальша робота

- **Keep Alive.** Перевірити надійність у довших сесіях, під час інших застосунків і переривань tvOS; одиничний успішний перенос не доводить гарантії фонового виконання.
- **Живі перевірки — з окремим дозволом на TV.** Перемотування, перезапуск, видалення торента й очищення кешу; виправляти лише відтворені проблеми.
- **Стан і конкурентний доступ.** Переглянути менеджер та збереження fast-resume, не обмежуючись вибором файлу.
- **Вибір посилань — на потім.** Розглянути список знайдених на сторінці magnet/.torrent-посилань замість вимоги точного наведення.

Референси: [архітектура](TORRENTS.md), [передача контексту](TORRENT_HANDOFF.md).

## Межі майбутніх рішень

- Перші UI-кандидати: повернення фокусу, контекстні підказки, підтвердження дій і запасні мініатюри; сітка обраного й автодоповнення потребують окремого погодження.
- Перед поверненням до закритого чи відхиленого напрямку читати dev history та чинні локальні правила; не трактувати старий експеримент як план реалізації.
- Використовувати UIKit, погоджене меню, ON/OFF-бейджі та документовані кнопки пульта. Не переносити Android-специфічні API чи телеметрію Firefox TV.
- Firefox iOS — референс для WebKit/фреймів/вкладок; Firefox TV — для remote UX; libtorrent — для завантаження/відновлення, iTransmission — для інтерфейсу торентів. Перевіряти поточну сумісність, зберігати ліцензії й атрибуцію.
