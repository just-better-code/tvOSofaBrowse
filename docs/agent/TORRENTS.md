# Torrents on Apple TV

The browser embeds libtorrent and TVVLCKit. Open **Torrents** from the menu or click a magnet or HTTP(S) `.torrent` link on a page. New torrents start with files skipped until you choose which to download. The library groups files by path; select a file or all descendants of a folder. **Play Now (Priority)** enables the selected file. TVVLCKit plays verified pieces through a loopback HTTP range server while the remainder downloads, then opens completed files directly on later playback. Torrent data lives in `Library/Caches/BrowserTorrents`; tvOS may purge it between app launches.

For streaming, the manager gives the selected file a high file priority, requests its first and last pieces with deadlines, and gives urgent deadlines to pieces requested by VLC's HTTP range reads. It clears libtorrent's sequential-download flag on playback because [libtorrent recommends piece deadlines for streaming](https://www.libtorrent.org/single-page-ref.html); sequential mode can delay a needed tail or seek piece. A completed file uses its local URL on the next playback. Keep the numeric torrent, HTTP, and VLC diagnostics in Debug until the user separately asks to remove them.

Playback positions are small numeric values in app preferences, keyed by torrent hash and file index. VLC saves them during playback, on pause, and before closing or switching files, then seeks after the reopened media becomes seekable. Finishing a file or approaching its end clears that position. Reset and Remove clear positions for that torrent; Reset All applies the same asynchronous reset to every listed torrent; Delete All removes every listed torrent and clears its playback positions. The player keeps its short seek-button presses at 10 or 30 seconds; a held button repeats 20- or 60-second jumps, with the latter doubling after ten seconds of continuous hold. The seek-button long press takes priority over the player's general Center-hold context action.

File selection is saved in `Metadata/sources.plist` and applied to libtorrent as file priorities. The folder action batches its descendant file indices so metadata is written once, and enabling a selection resumes the torrent. libtorrent 1.2 offers `file_priority` and `prioritize_files`, but its removal flag deletes the whole torrent payload. Priority zero does not move an already-created file back into the part file. Directly unlinking a selected file while the torrent is active would leave cached pieces and resume data out of sync, potentially affecting pieces shared with neighboring files. Do not expose individual file/folder payload deletion until a coordinated recheck and synchronization workflow is designed and verified. Whole-torrent Reset uses libtorrent's asynchronous `delete_files` operation, waits for `torrent_deleted_alert`, discards stale resume state, and re-adds the retained source with all files skipped. A failed deletion restores the original source and forces a recheck. The other supported removal actions are whole-torrent Remove and Delete All.

During device work, a real completed file was returned by libtorrent but vanished when the folder UI excluded every file reported as padding. Keep regular media paths visible and retain a flat-list fallback if grouping yields no rows. The TV user confirmed the file list returned and the right-hand per-file download control worked; folder-wide selection and Reset still lack a direct device observation.

Run `scripts/bootstrap-torrent-deps.sh` and `scripts/bootstrap-vlc-deps.sh` once before building. They download libtorrent 1.2.17, Boost 1.69, and the official TVVLCKit 3.7.3 tvOS device binary into ignored `.deps/`, with pinned SHA-256 checksums. The libtorrent binary is from [libtorrent-Apple](https://github.com/danylokos/libtorrent-Apple), built from [libtorrent](https://github.com/arvidn/libtorrent), which uses the BSD license. Boost uses the [Boost Software License](https://www.boost.org/users/license.html). [TVVLCKit](https://github.com/videolan/vlckit) is provided by VideoLAN under LGPL-2.1-or-later; its license is retained in `.deps/TVVLCKit-LICENSE.txt` after bootstrap.

The **Keep Alive** menu toggle loops silent audio in the background. A no-torrent device probe with it on measured about 230 seconds of active execution with a five-second longest gap, recorded during the former external-VLC investigation. External VLC handoff and its library icon were removed on 2026-10-11 at the user’s request. The loopback HTTP range server remains exclusively for embedded VLC torrent playback. Torrent playback offers MP4, M4V, MOV, MP3, M4A, MKV, and AVI through the embedded VLC engine; supported codecs still depend on the particular file and tvOS hardware. The library's hint reports the total torrent cache size, including downloads that belong to listed torrents. **Reset All** runs the existing per-torrent reset for every listed entry, retaining sources with all files skipped. **Delete All** requests removal of every listed torrent and its cached files through libtorrent. Both actions require confirmation. Removing one torrent requests deletion of its cached payload, metadata, and saved fast-resume state. Libtorrent checkpoints verified pieces in the cache to avoid a full file check on every launch; this is still under device verification. If tvOS purges the payload, libtorrent must download missing pieces again.

The app registers tvOS refresh and processing tasks and requests runtime when a manually started torrent remains incomplete. It checks the system Background App Refresh status before submitting and responds to a change in that status. tvOS can defer, interrupt, or omit a task. The Debug build also submits a probe-only request with no torrent; its results are available in Debug. A background task registration or submission does not establish that the system actually ran it or that a torrent transferred.
