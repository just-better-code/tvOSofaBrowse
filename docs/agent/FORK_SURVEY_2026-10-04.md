# Upstream fork survey — 2026-10-04

This is a research note, not a feature commitment or verification on tvOSofaBrowse. Public upstream forks were compared with [jvanakker/tvOSBrowser](https://github.com/jvanakker/tvOSBrowser). The most useful ideas and their fit with this project's current behavior follow.

| Source | Useful idea | Assessment |
| --- | --- | --- |
| [ZaynJarvis/tvos-browser](https://github.com/ZaynJarvis/tvos-browser/tree/b1dfad2253d8772adb05e64bb074d01d36df643b) | Synthetic pointer/mouse transitions plus `:hover` CSS-rule mirroring; pointer-targeted inner scrolling; D-pad spatial navigation; phone/Mac remotes. | Highest priority as a **hover technique**. Its [agent is injected only into the main frame](https://github.com/ZaynJarvis/tvos-browser/blob/b1dfad2253d8772adb05e64bb074d01d36df643b/_Project/Browser/BrowserWebView.m#L546-L548), so cross-origin iframe routing must be designed locally. See the [iframe handoff](plans/iframe-player-controls.md#candidate-from-an-upstream-fork-css-hover-emulation) for the mechanism and limitations. Its D-pad mapping conflicts with our browser and fullscreen-player button contract, and remote clients are a separate feature. |
| [alan-maldonado/tvOSBrowser](https://github.com/alan-maldonado/tvOSBrowser/tree/59daab63a09562a40010bdd4e416fc7732aa5169) | tvOS dialogs for JavaScript `alert`, `confirm`, and `prompt`; a native video [transport HUD](https://github.com/alan-maldonado/tvOSBrowser/blob/59daab63a09562a40010bdd4e416fc7732aa5169/_Project/Browser/BrowserNativeVideoPlayerViewController.m) with elapsed/remaining and buffered progress. | Review only if those specific UI gaps are observed in our app. The native HUD does not fix embedded website controls. |
| [Shibx12/tvOSBrowser](https://github.com/Shibx12/tvOSBrowser/tree/b03bfb82b15bdf314c169cf4aaf31b40e09c3c1c), [upstream PR #68](https://github.com/jvanakker/tvOSBrowser/pull/68) | UIScene lifecycle changes for launch issues on tvOS 26/27. | A compatibility lead if that launch failure is observed. A migration must account for our tab/history and torrent lifecycle. No current failure was verified here. |
| [Upstream PR #69](https://github.com/jvanakker/tvOSBrowser/pull/69) | Avoid synchronous JavaScript re-entry during cursor movement. | Keep in mind when changing hover. Our current hover check is asynchronous; this PR is not a direct patch to adopt. |

The ZaynJarvis fork calls its hover "real" in its [README](https://github.com/ZaynJarvis/tvos-browser/blob/b1dfad2253d8772adb05e64bb074d01d36df643b/README.md), but its [source](https://github.com/ZaynJarvis/tvos-browser/blob/b1dfad2253d8772adb05e64bb074d01d36df643b/_Project/Browser/BrowserPageAgent.js) dispatches synthetic events and mirrors CSS selectors. These events remain untrusted. A cross-origin stylesheet without CORS cannot be read by its page script; trusted-input-only controls remain unresolved. The survey did not build or run any fork.
